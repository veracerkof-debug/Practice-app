# Раздача в своей сети: Melete в браузере любого телефона (проработка, 2026-10-22)

**Статус:** шаг 1 сделан на компьютере (22.10): вход открытый и закрытый, тексты, аккорды, сет-лист, записи по одной
песне, «за лидером» с передачей ведения. Ответы автора и что сделано — `DECISIONS.md`, «Раздача в своей сети: ответы
автора». Ниже — исходная проработка: варианты, технологии, тонкости и следующие шаги.

## Идея автора
На компьютере (или телефоне) с Melete включается раздача. Любой человек в той же сети Wi-Fi — с айфоном, чужим
Android, планшетом — открывает в браузере адрес (или наводит камеру на QR-код) и видит Melete: песни, тексты, аккорды,
сет-лист; может слушать записи. Ничего не добавляет и не меняет. Записи подгружаются по одной, когда их открывают, и
лежат у гостя, пока он подключён; отключился — стираются.

Где это нужно: репетиция группы, команда прославления, урок с учеником, ансамбль. Лидер готовит сет-лист у себя —
у всех в зале он на экранах, без установки приложения и без интернета.

## Как это делают другие (правило 10: учимся, не копируем; сверить перед работой)
- **Holyrics** — свой веб-сервер в локальной сети: музыканты открывают в браузере страницу с текстом и аккордами
  текущей песни. Мы с Holyrics уже связаны (загрузка песен), автору он знаком.
- **ProPresenter** — «сценический экран» и пульт для музыкантов по локальной сети.
- **OnSong** (OnSong Connect) и **SongbookPro** — ведущий листает, у остальных песни переключаются сами
  («следовать за ведущим»). Но у них нужно установленное приложение на каждом устройстве — у нас нет.
- **Plex** — как получить настоящий HTTPS внутри домашней сети (см. «Защищённое соединение»).
- **LocalSend, PairDrop** — передача в локальной сети без облака; LocalSend мы уже принимаем на Windows.
Отличие Melete: гостю не нужно ничего ставить, работает на любом телефоне, всё остаётся в комнате.

## Как это устроено
```
Хозяин (компьютер Windows / телефон Android)              Гость (любой браузер в той же сети)
  Melete ──► сервер раздачи (порт, свой для гостей)  ◄──── http://192.168.1.5:53320  (или QR-код)
            ├─ гостевая страница (лёгкая сборка)          гостевая страница: песни, текст, аккорды,
            ├─ API только для чтения                       сет-лист, плеер; кэш — пока подключён
            └─ события «лидер переключил песню»  ───────►  страница открывает песню сама
```
- **Сервер раздачи — отдельно от синхронизации.** Синхронизация (`src/core/sync.js`, порт 53319) даёт полный
  доступ к данным по ключу. Раздача — только чтение и только то, что хозяин выбрал. Другой порт, другие адреса,
  никаких ключей синхронизации гостю.
- **Гостевая страница — отдельная маленькая сборка** (вход Vite `guest.html`): список песен, страница песни (текст и
  аккорды через `src/music/lyrics.js`, сдвиг тональности через `src/music/transpose.js`, схемы аккордов), сет-лист,
  простой плеер. Без ядра, модулей, звукового движка и моделей — несколько сотен килобайт, грузится мгновенно.
  Хозяин отдаёт её из своих файлов: Windows — из ресурсов, встроенных в программу (Tauri отдаёт встроенные файлы по
  пути), Android — из ассетов APK.
- **API только для чтения**, по смыслу:
  `GET /g/v1/hello` (имя хозяина, что раздаётся), `GET /g/v1/songs` (список: название, тональность, темп, метки),
  `GET /g/v1/song/:id` (текст с аккордами, заметки, капо), `GET /g/v1/setlist`, `GET /g/v1/audio/:id` (запись),
  `GET /g/v1/live` (поток событий «лидер на песне X»).

## Компьютер (Windows) — первым
- **Сервер уже есть.** В программе для Windows работает свой HTTP-сервер для связи с телефоном (`src-tauri/src/sync.rs`,
  `tiny_http`) и приём LocalSend. Раздача — второй такой сервер с отдельным портом. Логику (что отдать) решает окно,
  как в синхронизации; тяжёлое — файлы и поток аудио — отдаёт Rust напрямую, чтобы не гонять мегабайты через окно.
- **Переключатель «Раздавать песни в сети»** в «Данных и копиях» (сеть — только по воле человека), рядом QR-код и адрес.
  Брандмауэр Windows спросит разрешение — подсказка заранее.
- **Сильный компьютер делает тяжёлое за гостя** (см. «Аудио»): минус без вокала, сдвиг тональности — считает хозяин
  и отдаёт готовый файл.

## Телефон (Android) — вторым
- **Сервер на телефоне.** Свой маленький HTTP-сервер в нативном плагине (на `ServerSocket` или готовая лёгкая
  библиотека с лицензией, совместимой с GPL — например NanoHTTPD, BSD). Отдаёт гостевую страницу из ассетов APK,
  данные — через окно приложения, как на компьютере.
- **Жить в фоне.** Android останавливает фоновые приложения. Нужна служба переднего плана с уведомлением «Раздача
  песен: 5 гостей» (как у плеера) и блокировка Wi-Fi от засыпания. Тип службы и правила Google Play для неё — сверить
  (Android 14–15 строго ограничивает типы служб и время некоторых из них).
- **Батарея.** Раздача держит Wi-Fi и процессор: только по переключателю, выключается сама через N часов без гостей.
- **Когда нет Wi-Fi.** Телефон хозяина включает точку доступа — гости подключаются к ней и открывают адрес телефона.
  Работает в зале, на улице, в церкви без интернета. Нужно проверить, как Android отдаёт адрес в режиме точки доступа.

## Как гость находит адрес
- **QR-код** на экране хозяина — главный путь: навёл камеру, открылось. Адрес внутри QR, без ввода.
- **Короткое имя `melete.local`** — через mDNS (Bonjour). Айфоны понимают такие имена; Android — с оговорками
  (зависит от версии). На Windows объявлять имя можно из Rust (крейт mDNS-SD), на Android — через системную службу
  обнаружения. Хорошо как дополнение, полагаться только на него нельзя.
- **Обычный адрес** `192.168.1.5:53320` — запасной путь, крупно на экране, как в синхронизации.
- **Сайт вроде «melete.com» ходить в домашнюю сеть не может.** Браузеры запрещают защищённой странице из интернета
  обращаться к адресам локальной сети (смешанное содержимое и Private Network Access в Chrome). Поэтому гость
  открывает адрес самого хозяина, а не сайт. Сайт может только показать подсказку «как подключиться».

## Защищённое соединение — главная тонкость
Страница по `http://192.168…` для браузера «незащищённая». Из-за этого у гостя НЕ работают:
- AudioWorklet — наш движок плеера (Signalsmith: скорость и тональность), метроном на тиках;
- service worker и Cache API — офлайн-режим, установка как приложения (PWA);
- Wake Lock — запрет гасить экран (важно: текст на сцене не должен гаснуть);
- микрофон и камера, буфер обмена.
Работают: обычный `<audio>`, Web Audio без AudioWorklet (воспроизведение, громкость, смесь дорожек), IndexedDB,
localStorage, Server-Sent Events, WebSocket.

Варианты:
1. **Жить на http и не нуждаться в защищённом.** Гостевая страница проста: текст, аккорды, `<audio>`. Тяжёлое (сдвиг
   тональности, минус) считает хозяин. Экран не гаснет — известным приёмом с беззвучным зацикленным видео (работает
   и на iOS без Wake Lock). **Рекомендую начать с этого.**
2. **Настоящий HTTPS внутри сети, как у Plex.** Каждому хозяину выдаётся сертификат на имя вроде
   `192-168-1-5.<id>.melete.app`, общественный DNS отвечает на это имя локальным адресом. Браузер видит доверенный
   HTTPS — работает всё, даже установка как приложения. Цена: нужен наш домен, свой DNS и выдача сертификатов (сервер
   в интернете и обращение к нему при включении) — это против «без облака», плюс некоторые роутеры блокируют ответы
   DNS с локальными адресами. Отложить; вернуться, если гостям понадобится полный плеер.
3. **Самоподписанный сертификат** (как LocalSend между своими приложениями) — в браузере гость увидит страшное
   предупреждение. Не годится.

## Аудио
- **По одной песне, по запросу.** Гость открыл песню — пошла её запись. Сервер обязан отвечать на запросы диапазонов
  (HTTP Range, ответ 206): без этого Safari на iPhone не перематывает и часто не играет вовсе.
- **Сжатие.** Наши дорожки — WAV, ~10 МБ в минуту на дорожку; песня из 4 дорожек — 150+ МБ, по Wi-Fi на 20 гостей —
  много. Хозяин один раз перекодирует в AAC (M4A) — Safari и Android играют его везде, кодировщик встроен и в Windows
  (Media Foundation), и в Android (MediaCodec): без новых зависимостей. Кэш перекодированного — у хозяина.
- **Минус и дорожки — смесь у хозяина.** Гость выбирает «без вокала» или «только бас и ударные» — хозяин собирает
  смесь и отдаёт одним файлом. Гостю не нужно держать 4 дорожки в памяти телефона (на iPhone это сотни мегабайт).
  Вариант для сильных телефонов — дорожки по отдельности и смесь в Web Audio у гостя.
- **Сдвиг тональности — у хозяина.** На http нет AudioWorklet, значит у гостя нет Signalsmith. Хозяин отдаёт запись,
  уже сдвинутую на нужное число полутонов (тот же Signalsmith в окне или в Rust), и кэширует. Скорость — `playbackRate`
  у гостя (с изменением высоты) или тоже у хозяина.
- **«Лежит, пока подключён».** Кэш гостя — IndexedDB (работает и на http), с меткой сессии раздачи. Хозяин выключил
  раздачу, гость не видит сервер несколько минут или пришла новая сессия — кэш стирается. Ограничение размера
  (например, последние 5 песен). Честно: сохранить файл упорный человек сможет — это порядок работы, не защита.

## Режим «за лидером» — главное, ради чего это стоит делать
- Лидер (хозяин или выбранный гость с правом) открывает песню — у всех она открывается сама. Поток событий —
  Server-Sent Events: простой, работает на http, переподключается сам; `tiny_http` умеет отдавать ответ потоком.
- **Каждый — под свой инструмент.** Гость выбирает роль: вокал (только текст, крупно), гитара (аккорды со своим
  капо), клавиши, духовые in B♭ / in E♭ (аккорды сдвинуты под его строй — саксофон, труба). Лидер сдвинул тональность —
  у каждого пересчиталось под его роль. Этого нет у большинства приложений.
- Прокрутка за лидером — по желанию (у вокалиста да, у гитариста своя).
- **Общий счёт и щелчки метронома по Wi-Fi — нет.** Задержка сети 5–100 мс плавает — для звука это непригодно. Видимая
  доля (мигающая точка) с подстройкой часов — возможно позже; звук — каждый со своего метронома или из общего пульта.

## Доступ и приватность
- **Что раздавать** выбирает хозяин: один сет-лист (по умолчанию), выбранные песни или всю библиотеку. Личное
  (занятия, статистика, профиль, календарь, Библия) не раздаётся никогда.
- **Вход:** QR-код с одноразовым токеном раздачи. Режим «спрашивать»: хозяин видит «Иван хочет подключиться» —
  разрешить. Список гостей, выгнать одного, выключить всё одной кнопкой.
- **Аудио — отдельный переключатель** («тексты и аккорды» / «и записи»): записи могут быть чужими или личными.
- В своей сети по http трафик можно подслушать — для текстов песен это приемлемо; сказать в подсказке.
- Без входа гостя в аккаунт и без сбора данных — гость ничего о себе не сообщает, кроме имени по желанию.

## Тонкости гостевых браузеров
- **iPhone:** звук только после касания (первое «▶» — кнопкой); при блокировке экрана Safari может остановить звук;
  `.local` понимает. **Android Chrome:** то же про звук; `.local` — не везде.
- Язык гостевой страницы — по языку браузера (ru, uz, en), те же ключи переводов.
- Ночной режим и крупный шрифт — сразу, как на нашей «Сцене» (`screens/stage.js`).
- Связь пропала — страница показывает «Нет связи с хозяином», последняя песня остаётся на экране.

## Предлагаемый порядок
1. **Компьютер: раздача текста и аккордов.** Переключатель, QR-код, гостевая страница, API только для чтения,
   выбор, что раздавать. Проверка на iPhone и Android.
2. **Аудио.** Запись по одной (Range, AAC), кэш до отключения; затем минус и сдвиг тональности у хозяина.
3. **«За лидером».** Поток событий, роли под инструмент, сдвиг под B♭/E♭.
4. **Телефон как хозяин.** Нативный сервер, служба переднего плана, точка доступа.
5. По необходимости — HTTPS как у Plex.
