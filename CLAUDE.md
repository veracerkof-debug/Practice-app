# CLAUDE.md — инструкция для Claude Code

Этот файл Claude Code читает в начале каждой сессии. Держи его коротким и актуальным.

## Проект в двух словах
**Melete** (логотип — «Μελέτη», греч. «упражнение, усердное занятие»; см. `DECISIONS.md`).
Приложение для практики музыкантов: учёт занятий и статистика (ядро) плюс набор инструментов-модулей
(метроном, тюнер, пианино, глайдер, терменвокс (руки перед камерой), пэды/дрон, лупер, теория, тренажёр слуха, помодоро, медиатека — продвинутый плеер с дорожками записи (вокал, ударные, бас…), нотами из записи, тональностью и темпом, табы и тексты, диктофон, спектр и шумомер).
Без рекламы, без трекинга, без давления «ежедневными сериями» — ритм недельный.
Бесплатное, с открытым кодом (GPL-3.0). Платформы: Android (Google Play, F-Droid), веб, Windows.

## Основной принцип: пространство работает на функцию
Каждый инструмент использует всё пространство экрана по максимуму — стильно и красиво, но прежде всего
каждый пиксель окна на телефоне работает на функцию. Рабочая поверхность (доска, клавиатура, страница, шкала)
занимает окно целиком; надписи, названия и украшения, не помогающие играть, — убираются. Управление — компактно,
в краю окна, одной полосой; подсказки и показания — поверх поверхности так, чтобы не перехватывать касания.
Это основание всего приложения: любой новый экран и модуль проверяется этим правилом.

## Второй принцип: жесты и понятность
Всё интуитивно понятно, близко к человеку, удобно и практично. Если действие можно сделать жестом — интуитивным,
красивым, понятным и стабильным (принято в телефонах: смахнуть, щипок, удержание, перетащить, двойное касание,
смахнуть шторку вниз) — оно делается жестом, а не кнопкой, и так — везде одинаково: современные телефоны это умеют,
это удобно и функционально, и мы этим пользуемся. Кнопка остаётся для тех, кто жест не знает, и для точной
донастройки (±1 мс, ±1 шаг), но жест не прячется за кнопкой.
Жесты не спорят с системой (край экрана — «Назад» Android) и не срабатывают случайно (поля ввода, клавиши,
полосы прокрутки — без жестов). Общие жесты — `src/ui/gestures.js` (смахивание, щипок) и `src/ui/hold.js`
(удержание, перетаскивание); карта всех жестов — `docs/gestures.md`, новый жест — строка туда.

## Третий принцип: надёжность — ошибка стоит денег
Приложение для профессионалов: на сцене, на записи, на репетиции с людьми. Сбой звука, потерянная запись или
зависший экран в нужный момент могут стоить музыканту денег и репутации. Поэтому: всё, что звучит, должно работать,
когда звучат все инструменты сразу и настройки меняются на ходу (узлы звука создаются один раз и не переподключаются,
правки — только параметрами и плавно); запись никогда не теряется молча (исходник пишется как есть, обработка —
отдельно); вживую и в файле звучит одинаково (те же узлы); любая новая функция проверяется под нагрузкой и
с ошибками устройств (нет микрофона, занят выход, фон). Стабильность важнее новой функции: сомнительное — не выпускаем.

## Четвёртый принцип: притягательность работает на практику
Приложение должно быть приятным, плавным и красивым настолько, чтобы к инструменту хотелось возвращаться. Соцсети этими же
приёмами удерживают человека у экрана; мы ими ведём его к инструменту. Мера успеха — не время в приложении, а время за
инструментом и рост. Проверка любой функции: она даёт больше играть или больше смотреть в телефон? Приятное начало и
возвращение, тёплый итог занятия, честная статистика — да. Серии, ленты, сравнение с другими, чувство вины, бесконечная
прокрутка — нет, даже если они «повышают вовлечённость». Внутри занятия приложение почти невидимо: метроном тикает, ноты
на экране, пальцы на грифе.

## Шесть свойств — проверка любого решения
**Минимализм** (ничего лишнего на экране и в настройках), **практичность** (каждая функция решает задачу музыканта),
**интуитивность** (понятно без инструкции и «дураку»), **кастомизируемость** (всё, что кто-то захочет изменить, —
настраивается, а умолчания хороши сразу: по-настоящему настраивать будут 1–2 %, остальным 98 % должно быть удобно как есть),
**стабильность** (см. третий принцип), **приятность** (см. четвёртый принцип: приятно так, чтобы хотелось играть). Язык интерфейса — лаконичный, точный,
профессиональный и при этом простой: короткие слова, без канцелярита и без шуток там, где человек работает.

## Стек
- Vite + чистый JavaScript (ES-модули). Без фреймворка: прототип написан на vanilla JS, это осознанно.
- CSS custom properties (темы светлая/тёмная/«Бумага»/OLED, акцентный цвет), container queries для размеров окон.
- Web Audio API (единый AudioContext, шины, микшер), YIN для тюнера.
- Хранение: localStorage (лёгкие данные) + IndexedDB (аудио, табы). Local-first.
- alphaTab (MPL-2.0) для табулатур, pdf.js (Apache-2.0) для нот и табов в PDF, шрифт Bravura (OFL), звуковой банк SONiVOX (Apache-2.0).
- Android: Capacitor. Windows: Tauri 2 (`src-tauri/`, системный WebView2; отличия от браузера — `src/core/desktop.js`: «Сохранить как», папка Melete, файлы при запуске, F11; дорожки — нативный ONNX Runtime в Rust, `src-tauri/src/demucs.rs`).
  **Только на Windows** (модели в `build/models.json` с `platform: windows` → `src-tauri/models/`, ресурсы установщика; телефон и веб их не видят): текст песни из записи — whisper.cpp (`src-tauri/src/lyrics.rs`, `src/audio/lyrics.js`, результат `rec.lyr`, строка в плеере, в песню, .lrc, в фоне после дорожек); улучшенное разделение — вокал Mel-Band RoFormer (`roformer.rs`) + HTDemucs по инструменталу; шумоподавление DeepFilterNet3 (`denoise.rs`, `src/audio/denoise.js`, новый файл рядом); приём файлов с телефона по протоколу LocalSend (`localsend.rs`, `src/core/localsend.js`, переключатель в настройках папки Melete).

## Правила работы
1. **Одна сессия — одна задача.** В конце — проверка; коммит с понятным сообщением на русском.
   **Коммит и отправка — только по слову автора.** Сначала работаем, дорабатываем и обсуждаем; автор может передумать.
   Claude не коммитит и не пушит, пока автор не скажет «отправляй» (или «внеси и отправь»). Проверки, сборки и
   тесты — без ограничений; изменения до команды живут в рабочем дереве. Правило действует и после очистки контекста.
2. **Не ломать существующее.** Перед изменением поведения — сверка с прототипом.
3. **Только офлайн-ресурсы.** Никаких CDN в рантайме: всё кладём в проект.
   Обращения к сети — только по нажатию кнопки: поиск песни в MusicBrainz (`src/core/songinfo.js`), проверка часов
   (`src/core/clock.js`) и загрузка песен из Holyrics в своей сети Wi-Fi (`src/core/holyrics.js`, нативный HTTP на Android). Исключение — обновление (`src/core/update.js`): в режиме «автоматически» раз в сутки при запуске запрос к api.github.com (решение автора 24.10.2026). `index.html` пропускает соединения только к своим файлам, MusicBrainz и api.github.com (Content-Security-Policy).
   У MediaPipe (терменвокс) встроенный сборщик статистики вырезается при сборке (`build/mediapipe.js`), сборка проверяет это.
4. **Зависимости — только GPL-совместимые.** Каждую новую добавлять в экран «Лицензии» и `LICENSES.md`.
5. **Никакой аналитики, рекламы, трекеров, сбора данных.** Микрофон и камера — только локальная обработка.
   Новую зависимость проверять на скрытые сетевые обращения (`grep https://` по коду пакета).
6. **Все строки интерфейса — через i18n** (`t('key')`), языки: ru (основной), uz (латиница), en.
   Тексты — нейтральные и официальные, без прямого обращения (ни «ты», ни «вы»).
   Прототип переводил интерфейс подстановкой по DOM — это временный костыль, заменяем на ключи.
7. **Доступность**: подписи `aria-label`, достаточный контраст, крупные цели касания (≥ 40 px).
8. **Размеры окон**: каждый модуль обязан нормально выглядеть в `full`, `half`, `quarter`, `strip`.
9. После значимых решений — строка в `DECISIONS.md`; после этапа — галочки в `ROADMAP.md`.
10. **Учиться у других.** Получив задание по любому модулю, сначала посмотреть, как это сделано у других (открытые проекты,
   известные приложения): какие функции и приёмы есть у них и нет у нас, что удобнее. Учиться — можно и нужно, брать чужой
   код и оформление — нельзя (лицензии, свой дизайн-код); решение — своё, в духе принципов выше. Найденное, но не взятое —
   строкой в `docs/next-2026-10.md`.

## Несколько чатов
Разработка идёт в нескольких чатах Claude: **общий** (принципы, решения, связь частей, вливание) и **тематические**
(модуль, идея, отдел). Общая линия — ветка `main`: из неё собираются сборки **dev** (релиз «dev»: «Melete DEV» —
отдельное приложение автора, `app.melete.dev`). Тестерам — **pre** (релиз «pre», `app.melete`, и веб-версия gh-pages):
только из ветки `pre` и только по слову автора «выпускай» (`git push origin main:pre` — то, что автор уже проверил в dev).
Всё новое сначала идёт в dev, потом в pre (DECISIONS 2026-10-24). Новое — обратимо и выключаемо; варианты (звуки, виды, алгоритмы) — в dev все с переключателями, в pre — только выбранный автором, без переключателей (`src/core/variants.js`). Обновление — само из релиза своего канала
(`src/core/update.js`); заметное новое для людей — запись в `src/core/whatsnew.js` (окно «Что нового» и описание релиза). Каждый чат работает в своей ветке `claude/…`, начатой от свежей `main`; там же идут
проверки в браузере (e2e). По слову автора «отправляй» работа чата вливается в `main` (сначала `git merge origin/main`
в свою ветку, проверки, потом в `main`), после этого собираются общие сборки. Тематический чат держится своей области
и общих файлов (`src/i18n/*.json`, `settings.js`, `index.js` ядра, стили, `DECISIONS.md`) касается точечно — строками,
без переписывания; решения пишет в `DECISIONS.md` новой записью. Расхождения при вливании разбирает общий чат.

## Перенос из прототипа — сделано
Убрано: всё от Claude-артефактов (`window.claude.*`, db capability, `/_blob/...`, загрузки), CDN (alphaTab и звуковой
банк — в проекте), мёртвый код тренажёра ритма, тестовый переключатель Pro. Контент автора (урок Caprice 24, его табы)
в репозиторий не попадает. Новое из прототипа не возвращать.

## Коды и тестерские функции — убраны
Коды доступа, проверка создателем (правка чисел), фиктивная история занятий и личные обращения удалены (2026-10);
«Минимал» доступен всем. `src/core/cleanup.js` один раз возвращает настоящие данные из копии, если на устройстве шла проверка.

(`settings.church`, по умолчанию выключен). Демо-набор (`src/core/demo.js`,

## Команды
- `npm install` — установить зависимости (один раз после клонирования)
- `npm run dev` — сервер разработки, доступен с телефона по Wi-Fi (`http://<IP компьютера>:5173`)
- `npm run build` — сборка в `dist/`
- `npm run preview` — посмотреть собранную версию
- `npm test` — тесты (Vitest). `tests/parity.test.js` сверяет ядро с функциями из `legacy/practice.html`
- `npm run e2e` — сквозные проверки в браузере (Playwright + Chromium, `tests/e2e/*.spec.js`, общее — `tests/e2e/melete.js`; сервер Vite поднимается сам). Идут в GitHub Actions при каждом пуше (`.github/workflows/e2e.yml`); красное — чинить до того, как автор возьмёт сборку. В контейнере Claude: `PW_CHROMIUM=/opt/pw-browsers/chromium npm run e2e`. Новая функция — строка-проверка туда же.
- `npx cap sync android` / `npx cap run android -l --external` — Android с живой перезагрузкой
- Веб-версия (отдельная от APK, для знакомства; память — в браузере: постоянное хранилище и service worker, `src/core/webmemory.js`, `public/sw.js`) собирается GitHub Actions (`.github/workflows/web.yml`) → ветка `gh-pages` → https://veracerkof-debug.github.io/melete-app/
- Windows-установщик собирает GitHub Actions (`.github/workflows/windows.yml`, Tauri): `main` → релиз «dev», `Melete-Dev-Setup.exe` («Melete DEV», `src-tauri/tauri.dev.conf.json`); ветка `pre` → релиз «pre», `Melete-Setup.exe`; локально — `npm run win` (нужны Rust и Windows), `npm run win:dev` — окно с живой перезагрузкой
- Откат pre: каждая сборка pre помечена `pre-<N>`; «откати pre на N» — `git push --force origin pre-N:pre` (та же программа с бóльшим номером приходит обновлением, данные остаются). Перед выкладкой APK проверяется на эмуляторе (`build/apk-smoke.sh`); данные прошлых версий — `tests/compat.test.js`
- Ключ подписи APK — только в секретах GitHub (`BETA_KEYSTORE_B64`, `BETA_STORE_PASSWORD`), в репозитории его нет (репозиторий открытый)
- APK собирает GitHub Actions (`.github/workflows/android-beta.yml`): `main` → релиз «dev», `Melete-Dev.apk` («Melete DEV», `app.melete.dev`); ветка `pre` → релиз «pre», `Melete-PreRelease.apk` (Melete, версия 1.2-pre); последней в релиз — метка сборки `android-<N>.ver` (`windows-<N>.ver`), по ней приложение видит готовую сборку; тот же файл pre — и в старом релизе «beta» (`Melete-Beta.apk`), чтобы старая ссылка давала свежую сборку
