# CLAUDE.md — инструкция для Claude Code

Этот файл Claude Code читает в начале каждой сессии. Держи его коротким и актуальным.

## Проект в двух словах
**Melete** (логотип — «Μελέτη», греч. «упражнение, усердное занятие»; см. `DECISIONS.md`).
Приложение для практики музыкантов: учёт занятий и статистика (ядро) плюс набор инструментов-модулей
(метроном, тюнер, пианино, глайдер, терменвокс (руки перед камерой), пэды/дрон, лупер, студия-черновик, теория, тренажёр слуха, помодоро, медиатека, табы и тексты, диктофон, спектр и шумомер).
Без рекламы, без трекинга, без давления «ежедневными сериями» — ритм недельный.
Бесплатное, с открытым кодом (GPL-3.0). Платформы: Android (Google Play, F-Droid), веб, позже Windows.

## Основной принцип: пространство работает на функцию
Каждый инструмент использует всё пространство экрана по максимуму — стильно и красиво, но прежде всего
каждый пиксель окна на телефоне работает на функцию. Рабочая поверхность (доска, клавиатура, страница, шкала)
занимает окно целиком; надписи, названия и украшения, не помогающие играть, — убираются. Управление — компактно,
в краю окна, одной полосой; подсказки и показания — поверх поверхности так, чтобы не перехватывать касания.
Это основание всего приложения: любой новый экран и модуль проверяется этим правилом.

## Второй принцип: жесты и понятность
Всё интуитивно понятно, близко к человеку, удобно и практично. Если действие удобно и привычно делать жестом
(принято в телефонах: смахнуть, щипок, удержание, перетащить, двойное касание, смахнуть шторку вниз) — оно делается
жестом, и так — везде одинаково. Кнопка остаётся для тех, кто жест не знает, но жест не прячется за кнопкой.
Жесты не спорят с системой (край экрана — «Назад» Android) и не срабатывают случайно (поля ввода, клавиши,
полосы прокрутки — без жестов). Общие жесты — `src/ui/gestures.js` (смахивание, щипок) и `src/ui/hold.js`
(удержание, перетаскивание); карта всех жестов — `docs/gestures.md`, новый жест — строка туда.

## Стек
- Vite + чистый JavaScript (ES-модули). Без фреймворка: прототип написан на vanilla JS, это осознанно.
- CSS custom properties (темы светлая/тёмная/«Бумага»/OLED, акцентный цвет), container queries для размеров окон.
- Web Audio API (единый AudioContext, шины, микшер), YIN для тюнера.
- Хранение: localStorage (лёгкие данные) + IndexedDB (аудио, табы). Local-first.
- alphaTab (MPL-2.0) для табулатур, pdf.js (Apache-2.0) для нот и табов в PDF, шрифт Bravura (OFL), звуковой банк SONiVOX (Apache-2.0).
- Android: Capacitor. Windows: позже, Tauri.

## Архитектура
- **Папки**: `src/core` (ядро), `src/modules/<id>` (инструменты), `src/audio` (звук), `src/i18n` (переводы),
  `src/ui` (общие элементы), `src/styles` (токены темы `tokens.css` и базовые стили). Точка входа — `src/main.js`.
- **Ядро** (`src/core`): `store.js` (данные и хранение), `session.js` (сессии, учёт инструментов вне сессии),
  `stats.js` (статистика, ударный режим), `library.js` (песни и метки), `settings.js` (цель, дни, тема, функции),
  `pomodoro.js` (таймер помодоро — в ядре, потому что влияет на паузу сессии), `stopwatch.js` (секундомер «сколько я играю»),
  `calendar.js` (события календаря: повторы, раскладка, `.ics`), `profile.js` (профиль: инструменты, уровень, опыт до приложения),
  `files.js` (аудио, видео и табы пользователя в IndexedDB — общие для медиатеки, табов и песен).
  `songinfo.js` — поиск песни в MusicBrainz и тональность песни; `songanalyze.js` — темп и тональность по записи (анализ — `src/music/analyze.js`).
  `activity.js` — признаки занятия (касания, звук, микрофон по желанию) и проверки бездействия; `nosound.js` — уведомление «Звука нет».
  `share.js` — обмен с командой: файл `.melete` (песни, табы, сет-лист; формат — `docs/share-format.md`), экраны — `screens/share.js`;
  `stage.js` — сет-лист и сцена (настройки песен в сет-листе; экран — `screens/stage.js`); `reminders.js` — напоминания о практике (уведомления телефона; лицо маскота — `notifymood.js`, картинки — `build/notifyicons.mjs`), `quotes.js` — слова маскота (стихи, истории музыкантов).
  `folder.js` — папка Melete на устройстве (Data, Media, Tabs, PDF, Lyrics; синхронизация в обе стороны), `foldersync.js` — когда синхронизировать; Android — `FolderPlugin.java`.
  `appicon.js` — иконка приложения на выбор (рисунки — `src/ui/appicons.js`, PNG — `build/appicons.mjs`, Android — `IconPlugin.java` и activity-ярлыки `IconActivities.java`).
  `log.js` — технический журнал на устройстве (3 ч, без личного); `report.js` — отчёт о проблеме (отправляет человек через «Поделиться»).
  `mastery.js` — лиги (самоцвет по часам практики в приложении; званий нет); `tama.js` — Мелета-тамагочи на занятии (`tamatexts.js` — реплики, экран — `src/ui/tama.js`).
  `recorder.js` — запись в инструментах (звук приложения, микрофон, видео модуля → медиатека; MIDI — сама игра, файл .mid; кнопка — `screens/rec.js`);
  `midi.js` — воспроизведение MIDI-записей в инструменте и MIDI-клавиатура (Android — `MidiPlugin.java`, веб — Web MIDI); инструмент с MIDI отдаёт `midiIn`/`midiStop`;
  `palettes.js` — палитры (у каждого инструмента свой оттенок); `demo.js` — демо-набор (песни, табы, ноты, записи `demoaudio.js`, события).
  `player.js` — управление звуком вне приложения: кнопки в уведомлении, плавающая кнопка, всплывающее окно (Android — `PlayerPlugin.java`, `FloatService.java`);
  `backup.js` — резервная копия с подписью (кто и когда): в папку Melete (`Data/Backups`) или через «Поделиться»; по частям — `backupparts.js`, выбор — `screens/backupsheet.js`;
  `reading.js` — чтение Библии и планы (свои — `screens/bibleplan.js`); `cleanup.js` — разовая очистка после проверок.
  Сохранять файлы на Android — только через «Поделиться» (`screens/share.js: sendFile`) или папку: скачивание ссылкой в WebView не работает.
  Логика без DOM, формат данных и ключи localStorage — как в прототипе (`practice.v1*`).
  `device.js` — настройки инструментов на устройстве (`practice.v1.tools`: микшер, пианино, пэды, тюнер…).
- **Звук** (`src/audio`): `context.js` (единый AudioContext, компрессор, реверберация), `mixer.js` (шины
  metro/piano/drone/media/theory), `synth.js` (звуки пианино, у каждого свои ручки; второй слой с громкостью и эквалайзером; 22 голоса), `grand.js` (рояль по записям Salamander, `public/piano/`), `drone.js` (пэды и тампура),

Сборка — `createAudio()` в `index.js`.
- **Музыка** (`src/music`): ноты и правописание (`notes.js`), тональности, гаммы, аккорды, интервалы (`theory.js`),
  строи струнных (`tuning.js`), текст с аккордами (`lyrics.js`), транспонирование по ступеням (`transpose.js`), темп и тональность по записи (`analyze.js`), гриф гитары по кадру (`fretboard.js`), схемы аккордов (`guitarchords.js`) и аккорд по пальцам (`fingering.js`), мелодии по подсказке (`melodies.js`), проект студии по образцу FL Studio: дорожки × паттерны, плейлист-песня, ноты, аккорды и их развёртка, шаги ударных (`project.js`), ноты проекта в MusicXML (`musicxml.js`), MIDI — запись игры и файлы .mid, MPE для скольжения (`midi.js`) — чистые функции, сверены с прототипом (`tests/music.test.js`).
- **Интерфейс** (`src/ui`): шторка, сообщение, подтверждение, переключатели, иконки (`index.js`), клавиатура (`keyboard.js`),
  пресеты (`presets.js`), удержание и перестановка жестом (`hold.js`: меню, `dragSort` — как значки на главном экране); движение — `src/styles/motion.css`; стили перенесены из
  прототипа с сохранением порядка правил (`ui.css`, `pane.css` — окно модуля, `screens.css`); кольцо цели и карточки статистики — `cards.js`. Модули монтирует
  `src/core/modules.js`, экраны ядра — `src/core/screens/` (`shell.js` — вкладки и общие действия, `home.js`, `songs.js`,
  `panel.js` — профиль, настройки, статистика, `tools.js`, `calendar.js`, `onboard.js` — регистрация, `session.js` — экран сессии с окнами, `mixer.js` — микшер сбоку);
  логика окон сессии — `src/core/workspace.js`; правовые тексты — `src/core/legal.js`.
- **Ядро**: песни, сессии, календарь, статистика, цели, ударный режим (по неделям), метки, данные и копии,
  оформление, языки, функции (вкл/выкл модулей), микшер, правовые экраны.
- **Модули**: каждый инструмент — отдельная папка, подключается по контракту из `MODULE_SPEC.md`.
  Реестр (`src/modules/index.js`) находит папки сам: `src/modules/` — встроенные, `src/modules-local/` — личные
  (в `.gitignore`). Шаблон — `docs/module-template/`. Вкладки внизу настраиваются (`settings.tabs`, `settings.tabsOff`).
  Ядро не знает внутренностей модулей; модули общаются с ядром только через `ctx`.
- **Две сборки**: `prod` (Google Play/F-Droid — только встроенные модули, без отладки) и
  `dev` (отдельный applicationId и иконка «DEV»: загрузка внешних модулей, живая перезагрузка,
  панель разработчика, тестовые флаги, отдельные данные).

## Правила работы
1. **Одна сессия — одна задача.** В конце — проверка и коммит с понятным сообщением на русском.
2. **Не ломать существующее.** Перед изменением поведения — сверка с прототипом.
3. **Только офлайн-ресурсы.** Никаких CDN в рантайме: всё кладём в проект.
   Обращения к сети — только по нажатию кнопки: поиск песни в MusicBrainz (`src/core/songinfo.js`), проверка часов
   (`src/core/clock.js`) и загрузка песен из Holyrics в своей сети Wi-Fi (`src/core/holyrics.js`, нативный HTTP на Android). `index.html` пропускает соединения только к своим файлам и MusicBrainz (Content-Security-Policy).
   У MediaPipe (терменвокс) встроенный сборщик статистики вырезается при сборке (`build/mediapipe.js`), сборка проверяет это.
4. **Зависимости — только GPL-совместимые.** Каждую новую добавлять в экран «Лицензии» и `LICENSES.md`.
5. **Никакой аналитики, рекламы, трекеров, сбора данных.** Микрофон и камера — только локальная обработка.
   Новую зависимость проверять на скрытые сетевые обращения (`grep https://` по коду пакета).
6. **Все строки интерфейса — через i18n** (`t('key')`), языки: ru (основной), uz (латиница), en.
   Тексты — нейтральные и официальные, без прямого обращения (ни «ты», ни «вы»).
   Прототип переводил интерфейс подстановкой по DOM — это временный костыль, заменяем на ключи.
7. **Доступность**: подписи `aria-label`, достаточный контраст, крупные цели касания (≥ 40 px).
8. **Размеры окон**: каждый модуль обязан нормально выглядеть в `full`, `half`, `quarter`, `strip`.
9. После значимых решений — строка в `DECISIONS.md`; после этапа — галочки в `ROADMAP.md`.

## Перенос из прототипа — сделано
Убрано: всё от Claude-артефактов (`window.claude.*`, db capability, `/_blob/...`, загрузки), CDN (alphaTab и звуковой
банк — в проекте), мёртвый код тренажёра ритма, тестовый переключатель Pro. Контент автора (урок Caprice 24, его табы)
в репозиторий не попадает. Новое из прототипа не возвращать.

## Коды и тестерские функции — убраны
Коды доступа, проверка создателем (правка чисел), фиктивная история занятий и личные обращения удалены (2026-10);
«Минимал» доступен всем. `src/core/cleanup.js` один раз возвращает настоящие данные из копии, если на устройстве шла проверка.
Новых механизмов, меняющих данные в обход обычного интерфейса, не добавлять. Исключение — отдельная сборка-демонстрация
(`src/showcase/`, …/Practice-app/show/): выдуманный музыкант и его история, своё хранилище, в APK не попадает. Приложение светское: всё христианское (Библия, стихи, цитаты, духовные песни) — только в церковном режиме
(`settings.church`, по умолчанию выключен). Демо-набор (`src/core/demo.js`,
`demoaudio.js`, `public/demo/`) — для всех, остаётся и в выпуске.

## Команды
- `npm install` — установить зависимости (один раз после клонирования)
- `npm run dev` — сервер разработки, доступен с телефона по Wi-Fi (`http://<IP компьютера>:5173`)
- `npm run build` — сборка в `dist/`
- `npm run preview` — посмотреть собранную версию
- `npm test` — тесты (Vitest). `tests/parity.test.js` сверяет ядро с функциями из `legacy/practice.html`
- `npx cap sync android` / `npx cap run android -l --external` — Android с живой перезагрузкой
- Веб-версия (отдельная от APK, для знакомства) собирается GitHub Actions (`.github/workflows/web.yml`) → ветка `gh-pages` → https://veracerkof-debug.github.io/Practice-app/
- Ключ подписи APK — только в секретах GitHub (`BETA_KEYSTORE_B64`, `BETA_STORE_PASSWORD`), в репозитории его нет (репозиторий открытый)
- Предрелизный APK собирает GitHub Actions (`.github/workflows/android-beta.yml`) при каждом пуше → релиз «pre», файл `Melete-PreRelease.apk` (Melete, версия 1.2-pre); тот же файл — и в старом релизе «beta» (`Melete-Beta.apk`), чтобы старая ссылка давала свежую сборку
